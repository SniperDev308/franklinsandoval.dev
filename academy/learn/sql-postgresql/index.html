01 / QUERY THINKING

Ask the database a precise question

READSELECT hostname, status FROM servers WHERE status = 'DOWN';CHANGEUPDATE servers SET status = 'MAINTENANCE' WHERE hostname = 'dc-app-01';REMOVEDELETE FROM test_events WHERE id = 42;
SUPPORT RULE

SELECT is observation. UPDATE and DELETE change state. In production, understand scope and authorization before modifying data.

02 / RELATIONSHIPS

Keys and JOINs

Primary key

Uniquely identifies a row in a table.

Foreign key

Represents a relationship to a key in another table and can help enforce referential integrity.

JOIN

Combines related rows from tables using a relationship condition.

WHERE

Filters rows. A missing or incorrect filter can radically change the scope of a query.

SELECT s.hostname, a.message
FROM servers s
JOIN alarms a ON a.server_id = s.id
WHERE a.active = true;

03 / POSTGRESQL SERVICE

Database health has layers

A PostgreSQL failure can be process-level, listener/configuration-level, authentication-level, network/policy-level, or application-level. Do not collapse all of them into “the database is down.”

Application→DNS/IP→TCP 5432→PostgreSQL→Auth / DB

systemctl status postgresql

ss -lntp | grep 5432

journalctl -u postgresql

psql -h 10.30.40.20 -p 5432 -U appuser -d appdb

04 / CONNECTION PATH

Interpret the symptom

Timeout

Often sends you toward path, firewall/policy, routing, or an unresponsive destination. Prove it with tests.

Connection refused

The destination responded but the requested TCP connection was rejected. Check listener/service state and configuration.

Authentication failed

Connectivity reached PostgreSQL far enough for authentication. Investigate credentials and access rules.

Database does not exist

The server is responding. Validate the requested database name and application configuration.

05 / HANDS-ON LAB

SQL support drill

  1. Create or use a practice PostgreSQL database.
  2. Create a servers table with id, hostname and status.
  3. Insert at least four rows.
  4. Use SELECT + WHERE to show only DOWN servers.
  5. Create an alarms table related to servers.
  6. JOIN servers and alarms.
  7. Verify PostgreSQL service state and TCP 5432 listener from Linux.
  8. Connect with psql and record what each successful step proves.
