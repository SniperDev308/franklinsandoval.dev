01 / ROUTING

The next-hop decision

A host compares the destination with its own subnet. Local destination: resolve a MAC and deliver on the LAN. Remote destination: send the frame to the default gateway. The router then selects a route toward the destination network.

Host→Subnet decision→Default gateway→Route table→Next hop
SUPPORT REFLEX

Check IP, mask, gateway and route before blaming the application.

02 / CORE SERVICES

DHCP and DNS

DHCP

Provides host configuration such as IP address, subnet mask, default gateway and DNS server information.

DNS

Resolves names to records such as IP addresses. A correct DNS result does not prove the destination service is reachable.

SCENARIO

app.company.local resolves to 10.20.30.15. Ping succeeds. HTTPS times out.

DNS has already done its job. What layer of the path should you test next?
Reveal reasoning

Test TCP 443 and the application service path. Check whether the port is reachable, whether a firewall or ACL blocks it, and whether the server is listening.

03 / TRANSPORT

TCP, UDP and ports

TCP

Connection-oriented transport with sequencing and reliability mechanisms. Common support examples include HTTPS and PostgreSQL connections.

UDP

Connectionless transport with lower overhead. DNS commonly uses UDP for many queries, while some protocols use UDP for discovery or broadcast behavior.

MENTAL CHECKPing works ≠ TCP 443 works

ICMP reachability and application-port reachability are different tests.

04 / POLICY + TRANSLATION

NAT/PAT and ACLs

NAT changes address representation between networks. PAT lets many sessions share an address by tracking transport-layer ports. ACLs apply permit/deny rules to traffic. During troubleshooting, ask where translation occurs and where policy can discard the flow.

06 / HANDS-ON LAB

Packet Tracer: routed application path

  1. Build two LANs separated by a router or Layer 3 switch.
  2. Assign each LAN a different IPv4 subnet.
  3. Configure host default gateways.
  4. Prove same-subnet and cross-subnet connectivity.
  5. Break one default gateway deliberately and observe the symptom.
  6. Restore it, then add an ACL that blocks one test flow.
  7. Document which test identifies each failure fastest.
